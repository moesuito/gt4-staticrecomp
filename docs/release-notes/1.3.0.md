# GT4Recomp 1.3.0

**Gran Turismo 4 and Gran Turismo 4 Spec II side by side, a multi-game launcher, and a launcher you can carry.**
You need your own disc image: Gran Turismo 4 (USA, v2.00) for the original game, and your own Spec II 1.10 image for
the mod. GT4Recomp ships no game files, no disc images and no Spec II files.

## Install or update

- Update from 1.2.x: accept the update in the launcher and say yes to the one administrator prompt. The update is
  silent, and the launcher starts again by itself when it is done. Your settings, saves and replays are kept: they
  stay in `%APPDATA%\GT4Recomp`, and the first start moves each game's files into its own `games\gt4` or `games\spec2`
  folder.
- New install: download **GT4Recomp-Setup-1.3.0.exe** and run it. The setup ships both game executables
  (`gt4.exe` and `gt4-spec2.exe`), the runtime files, the shaders and the licences.
- Portable: download **GT4Recomp-1.3.0-portable.zip**, unpack it anywhere and run `GT4Recomp.exe`. The portable build
  keeps its settings in `user\` and its large data in `data\` beside the executable, uses no registry or system
  folders, and updates by swapping the zip contents.
- Standalone game: the installed `gt4.exe` (Gran Turismo 4) and `gt4-spec2.exe` (Spec II) can be started
  directly, without the launcher. They find the installed game from their own folder, read the launcher's settings
  (`game.ini`, `gt4-gs.ini`) and use the same prepared files, cards and saves.

## New

- **Update channels and a version picker (TASK-109, Settings > General).** Below Language, **Channel** is Stable (default)
  or Beta. Stable gets the normal releases. Beta gets the release candidates (GitHub pre-releases `vX.Y.Z-rcN`) and the
  stable releases together, newest by version, so a Beta player also gets the final release when it ships; a draft is never
  offered. A candidate build with no stored choice starts on Beta. Going back to Stable never downgrades by itself: the
  launcher waits for a stable release newer than the installed build. The channel applies at once and is saved.
  **Version** is a dropdown read from GitHub each time the page opens (with a refresh button): Stable lists the stable
  releases by version, Beta lists the release candidates by publication date, with a newer stable release on top. The
  installed one is marked. Versions before 1.3.0-rc5 are not listed, because they cannot read the multi-game layout,
  settings schema 8 or the per-game save names. Choosing another version asks first; an older one (by version, any
  channel) shows a strong warning to back up the saves, with a button to the saves folder and an explicit "Install older
  version" button that never has the focus first. Yes runs the normal update path: download, `SHA256SUMS` check, the
  silent setup (or the portable zip swap), and the launcher closes.
- **Test builds carry their label.** The launcher version is `1.3.0-rc5` in About, on the home screen, in `version.json`
  and in the update decisions, with ordering `1.3.0-rc4 < 1.3.0-rc5 < 1.3.0 < 1.3.1-rc1` (rc numbers compare as numbers).
  Assets of a test build are `GT4Recomp-Setup-1.3.0-rc5.exe` and `GT4Recomp-1.3.0-rc5-portable.zip`.
- **Automatic graphics API and card (TASK-108).** Graphics API has a new first choice, Automatic: Vulkan when the card reports Vulkan 1.2, otherwise Direct3D 11. Graphics card (after Graphics API) picks the best card by default (a discrete card before integrated graphics, then the most video memory); the chosen card's name is written to the game's `Adapter` key. A stored card that is gone falls back to Automatic for that run. Explicit Vulkan on a card without Vulkan 1.2 runs with Direct3D 11, with a note.
- **No Vulkan gate for Direct3D runs.** The Vulkan 1.2 check runs only when Vulkan is the chosen API. Setup needs no GPU.
- **Game programs renamed.** `gt4vulkan.exe` is `gt4.exe` and `gt4vulkan-spec2.exe` is `gt4-spec2.exe` in the installer, the portable zip and the game folder. The installer removes the 1.2.x names; the build output names are unchanged.
- **New save, Export and Rename (Saves page, TASK-104).** New save parks the current save in a new `Save NN` slot and
  leaves Active empty, so the next Play starts a new profile; the card the last run left is harvested first and then kept in
  `backups`. Export writes the active save or a slot as a `.psu` file through the save dialog. Rename gives a save a display
  name of up to 40 characters, stored in `name.txt` beside the save; the folder names do not change, and the name moves with
  its save when saves are swapped. Keyboard: F2 renames the focused row. Gamepad: every button is reachable with the D-pad;
  the name itself is typed on a keyboard.
- **Gran Turismo 4 Spec II 1.10 as a second game.** The launcher identifies the Spec II disc by its executable
  (SCUS-97436), prepares the derived ELF from your own image (the 35 injector words and the data-segment split are
  applied ahead of translation) and starts `gt4-spec2.exe`. Same-executable variants are accepted, such as the
  Brazilian Portuguese translation, which only replaces language data. Any other SCUS-97436 program, including the
  unmodified GT4 Online Public Beta, is refused with a clear message because it needs its own patch map.
- **Each game has its own files.** Disc copy, prepared files, runtime card, save library and replays live under
  `games\gt4` and `games\spec2`; settings, controls, GSdx and textures are shared. The home screen has a game
  selector with each game's logo and its own Play/Install action, and the game you played last is selected at start.
- **What's new.** The home screen shows the release notes of the installed version, and can show the new version's
  notes when an update is available.
- **Automatic language.** The launcher follows the Windows display language and speaks English (en-US) and Brazilian
  Portuguese (pt-BR); General > Language overrides it. All launcher text, messages, settings, the About page and these
  notes are translated. The translation guide is [docs/TRANSLATING.md](../TRANSLATING.md).
- **Graphics API choice (GSdx).** Settings > Graphics > **Graphics API** writes `[EmuCore/GS] Renderer`:
  **Vulkan** (recommended, default), **Direct3D 12** (recommended) and **Direct3D 11** (for older PCs). OpenGL comes
  later: it needs an allow-list entry in a new gt4-gs release.
- **Portable build** (TASK-098): the same launcher as a zip that runs from any folder, with its own `user\` and
  `data\` folders and no registry or system folders.
- **Standalone game executable** (TASK-097): both game executables start on their own with the defaults built in
  (GSdx, 480p, 16:9 hold, automatic ultrawide, fullscreen, vsync) and the launcher's settings, so a double-click works
  and a missing piece shows a native message instead of a silent exit.

## Performance Mode (1.3.0-rc6)

- **The night flare readback no longer makes the game wait for the graphics card (TASK-116 step 1).** In Performance Mode
  the game used to stop once per frame to collect a 2 KiB visibility table from the GS process: it first drained the VU1
  worker (5.5 ms on the owner's George V run) and then waited for the reply (1.2 ms). Now only that one readback (128
  qwords, the 64x8 flare table) skips the drain and the wait, and its request is still posted to gt4-gs in stream order
  (one record per readback: the night record counts equal rc5's Performance mode). Every other readback (car icons,
  loading picture, thumbnail, photo mode) keeps the blocking drain and the round trip. Measured headless on a night race:
  the blocking drains went from 5,026 to 29 per run, the readback wait total from 2,329 ms (rc5 Performance mode) to
  46 ms. Part of the old 5.5 ms was the emulated CPU's own work of writing the frame's graphics data (now visible as
  `gs_drain`), so the net saving is about 2 to 3.5 ms per frame in the race. With Accurate readbacks (Performance Mode
  off) the game's stream is byte-identical to rc5 (`c091716e3cb40d79` on the night schedule).
- **No flares at all in Performance Mode (TASK-117).** That same table is answered with zeros, so the VU1 draws no lamp
  flare, no headlight glow, no halo and no sun glare. The visible sunlight is exactly what made weaker PCs drop frames on
  the Nordschleife when driving into the sun, and the halo was also the glow that could stay over a wall for one frame
  when a light passed behind it (the previous reply was one frame old); both are gone with the effect. Nothing else
  changes: the table is a presentation input only, the EE never reads it (`docs/GS-READBACK-STUDY.md` section 1.1), so
  physics, timing, AI, saves and replays cannot be affected, and the guest code is untouched, which keeps Performance
  Mode off byte-identical to rc5 by construction. Measured headless on the night schedule at 1x: 3,763 of 3,763 tables
  answered as zeros (probe `nz=0`), no readback wait, the same EE critical path as the previous-reply build (about 6.0 to
  6.5 ms in the race), and every frame before the race is byte-identical between the two (`GT4_GS_HIDE_FLARES=0` is the
  A/B switch that restores the previous reply). Owner test (2026-10-25): flares gone in v2.00 and Spec II, night and day,
  no other visual difference. The glows also stop drawing over the virtual rear-view mirror, a known GT4 artefact that
  PCSX2's GSdx shows too; that is a side effect of drawing no flare at all, and Accurate mode still shows it.
- **Why a local answer is safe.** The gate probe (`GT4_GS_READBACK_LOG=1`) showed that in Performance Mode gt4-gs does not
  answer with zeros, as the old help text implied: it returns real but stale pixels (139 distinct replies against 2,161 in
  Accurate mode). The local answer reproduced that one-frame-old behaviour deterministically in rc6 step 1; with TASK-117
  it returns the "every light hidden" value instead, which the VU1 already handles every frame (a fully occluded light
  samples zero, and split screen uses the constant `0x000000FF`).
- **The Performance Mode description in Settings now says what it really does.** It used to say that flares are skipped;
  it now says that the game stops waiting for the images, so the car icons next to the gap time can come out blank and the
  loading screen picture may be missing, and that the night lights and the sun glare are turned off (en-US and pt-BR).
- **Not in rc6: the guest-code cut of TASK-117.** A derived v2.00 ELF (four `jal` redirects into helper routines in the
  zero padding 0x495574-0x495FFF, with the `flare` EE library profile and a host block at 0x7F10) was built and tested,
  but every runtime-switched guest patch adds instructions on the switch-off path, and the emulated CPU's clock is
  instruction-counted: the VBlank lands at a different instruction and the night race diverges from rc5 on the first
  frame that draws flares. The host-side zero table above reaches the same visual result with no guest change at all, so
  the derived ELF stays on `task/116-117-flare-perf` as a documented dead end; the one thing only it could do is remove
  the GS-side 2 KiB download (the remaining cost at 8x), which belongs to TASK-116 step 2 (async download in gt4-gs).
- **One limitation of the zero table: split screen.** In split screen the game draws the headlights with a constant full
  visibility instead of sampling them (`docs/GS-READBACK-STUDY.md` 1.1), so those glows still show there; the sun is
  hidden as everywhere else. Single-player races and replays have no flare at all.

- **Launcher fixes from the first weak-laptop round (2026-10-26, TASK-118).** The launcher's six full-screen background
  animations kept compositing after Play and cost up to about 20% of a two-core laptop, which the F8 shows as the game's
  own EE CPU going from 6-12 ms to about 19.6 ms; they are now paused whenever the page is hidden, the window is unfocused
  or the game is running. A normal close is no longer reported as a crash (the launcher read `game.log` in the same instant
  the game wrote its last line; it now waits for the shutdown line and treats exit code 0 without one as a normal close).
  A Vulkan device loss is remembered: the stored Graphics API becomes Direct3D 11 and the player is told (the Intel HD 620
  reports Vulkan 1.3 but loses the device on entering the showroom). The Render scale slider is now additive: 100% is the
  automatic plan (1x on an integrated GPU, issue #89) and each 25% step adds one multiplier, so the laptop can reach 2x and
  3x instead of jumping from 1x to 4x at 125%.

## Changes

- **Saves of both games in one list (TASK-101 item 2).** Each row carries its game id (`gt4:Save 02`); activate,
  rename, export and delete act on that game's library; New save asks the game when two are installed; import needs
  no question, because each save names its game. Replays stay per game.
- **Launcher logs (TASK-112).** One file per launch, `logs\launcher-YYYYMMDD-HHMMSS.log`, with `INFO`, `WARN` and
  `ERROR` lines; the last 20 are kept; `logs\latest.log` has a header, the `ERROR` lines of the earlier kept sessions
  and the current lines. A 1.2.x `launcher.log` is renamed once to `launcher-legacy-<date>.log`. The game session folders
  are capped at the last 20, never the running one. About has Open latest log.
- **Export logs (TASK-111).** About (and a dialog after a crash or a lost graphics card) writes
  `GT4Recomp-logs-YYYYMMDD-HHMMSS.zip` to a folder the player picks: `latest.log`, the last 3 launcher logs, the last 3
  game sessions' `game.log` and `gt4-gs.ini`, the settings file and `system.txt`. The Windows user name and profile
  paths are masked in every text; no card, save, replay, disc image, prepared file or program is included. The result
  offers Open the folder and Report a problem on GitHub (the named link `report_problem`).
- **Game builds.** Both targets are built from one release recipe: the v2.00 game (`gt4vulkan.exe`, slice279) and the
  Spec II game (`gt4vulkan-spec2.exe`, slice280), with the target-aware hooks for the 16:9 hold, the 480p race display,
  the camera/HUD aspect and the license demo guard. The installer ships both executables; the launcher downloads
  gt4-gs 1.2.1.
- **The v2.00 game is frame-identical to 1.2.3.** Headless menus, day race and night race runs against the 1.2.3 build
  give the same frame-dump lists and the same GS stream hashes (measured; see [BUILD.md](../BUILD.md)).
- **Spec II license demo guard.** Spec II demos that our FPU cannot decrypt bit-exactly are skipped instead of
  crashing the game: 142 of the 256 demos on the disc are protected this way, and the rest play normally. The guard
  logs one line per skipped demo (`[license-guard]`).
- **The launcher's Spec II preparation reproduces the release tooling.** The Rust setup derives the same ELF as
  `scripts/spec2_elf_patch.py` (pinned SHA-256 `36f60b1a…`) from the same image; a test compares the two byte for byte
  when the owner's image is present.
- **One settings set for both games.** The launcher keeps one settings and controls set, one GSdx configuration and
  one `Textures` folder; only the executable, the disc image, the prepared files and the save folder differ per game.
- **Integrated GPU default (issue #89).** When the GPU the game uses is integrated (Vulkan device type 1, the only GPU
  with its own driver; with any discrete card the launcher behaves as before), a Render scale that is still the default
  (100%) plays at 1x: the internal frame is 640 x 448 (`display::INTEGRATED_DEFAULT_MULTIPLIER`), not k x scale. A changed
  scale keeps its multiplier, and the Render scale readout shows the plan the game gets. The stored value cannot tell an
  untouched 100% from a chosen one, so a 100% chosen on an integrated GPU also plays at 1x; every other value is unchanged.
  The decision is logged as `display: integrated GPU <name>: default internal 1x`. The device comes from the same Vulkan
  probe as the system check (`gt4l_platform::system::integrated_gpu_name`, read once per launcher process). The PCSX2 GS
  and the default Graphics API (Vulkan) are not changed.

## Fixes

- **rc5 hotfixes (laptop test).**
  - Setup identifies the disc image in place (SYSTEM.CNF serial, executable hash, known-image table) before any byte is
    copied, and again when setup starts; unknown, unsupported or changed files copy nothing. The first-run page is generic
    ("Install a game") and names the game once the image is identified; a stored Spec II choice no longer names it before.
    An Install button of one game with the other game's image installs what the image is and says so.
  - The copy bar: the later steps keep the finished copy's size and the copy step is drawn full with its final figure, so
    a poll that missed the last 100% value no longer leaves the bar short (Spec II 3.7 GB case).
  - GPU list: two integrated Vulkan devices (or two small-memory DXGI adapters) with the same PCI vendor and device id are
    one card; identical discrete cards with different LUIDs stay two. The log lists each raw entry (API, PCI ids, LUID).
  - Black window: the intro is looked up by the base version (`1.3.0-rc5` plays the 1.3.0 intro once), is not started
    while the page is hidden or on the setup page, ends by a 12 s hard limit, and logs start, end and skip.
- **Spec II saves were dropped at harvest (rc3 owner log).** Spec II writes `BASCUS-97436GAMEDATA`, which the library did
  not know; the save was skipped and the next Play built an empty card. Each game now has its own item names
  (`gt4saves::SaveNames`, from the game table: `save_folder`, `replay_prefix`). A library takes only its own items, a
  mixed card is split by game, and an item no game knows is reported on the Saves page. The Spec II replay prefix
  `BASCUS-97436` is not verified with a real Spec II replay.
- **GPU list duplicates (rc3 owner log).** Vulkan and DXGI entries are merged per physical card: exact repeats are
  dropped, and a card is matched by LUID when both APIs report one, else by PCI vendor and device id, else by name.
  The Vulkan probe reads `deviceID`, `driverVersion` and the LUID (`vkGetPhysicalDeviceProperties2`); DXGI reads
  `VendorId`, `DeviceId` and `AdapterLuid`.
- **Spec II copy bar stopped at about 85%.** The bar now uses the same byte total as its "x of x" figure.

- **Integrated graphics started at 3x and the GPU was lost (issue #89).** A 1440 x 900 screen gave k 3 (1920 x 1344
  internal) at the default Render scale, which an Intel UHD (integrated, Core i3-1005G1, 8 GB) cannot run: GSdx reported
  "Host GPU lost too many times" at 3x and at 2x. Now a session that ends with that GSdx text in its `game.log` shows
  a plain message in both languages ("Your graphics card stopped responding. Try a lower resolution (Graphics > Render
  scale) or switch Graphics API to Direct3D 11."); the matched line is kept in the launcher log, and the generic crash
  text is shown otherwise. The check looks for `Host GPU lost`, `device is probably completely wedged` and
  `VK_ERROR_DEVICE_LOST`; a bare "device lost" is not a marker, since the audio can report it too.
- **Saves dates followed English in pt-BR ("16 Oct 2026").** The Saves page formats its dates with the interface
  language (`Intl.DateTimeFormat` with the active locale), so pt-BR shows its own month names; en-US is unchanged.
- **Importing a PCSX2 memory card closed the launcher (issue #86).** The card reader followed directory entries and
  allocated lengths read from the card without limits: a directory that pointed back to an ancestor overflowed the stack
  and a 4 GB length aborted the process with no message. The reader now takes the card size, the allocation area and the
  indirect FAT list from the superblock, accepts 8, 16, 32 and 64 MB cards (with or without spare bytes), follows at most
  8 directory levels and visits each directory once (a loop is `corrupt card`), checks every length against the chain and
  the card before allocating, and the import is wrapped so a panic becomes a message that is logged with the file name and
  size. Clear messages say when a file is not a PS2 memory card, when the size is unsupported, when the card is damaged
  (with the reason) and when a card holds no Gran Turismo 4 save (and lists what it holds). Tests build synthetic cards in
  `gt4saves/tests/common` and cover each case (see TASK-104).
- **The first-start migration test was flaky.** The launcher test that moves a 1.2.x install into `games\gt4` failed
  four times and passed six when run repeatedly. A scanner or the Windows indexer can hold a freshly written file for
  a few milliseconds, and the rename then fails with a sharing violation instead of moving the folder. The move now
  retries that transient error five times (20-100 ms apart) before reporting a real failure, so a scan no longer delays
  the update; the test still checks that the files really moved.

## Known issues

- The Spec II replay prefix (`BASCUS-97436`) is untested with a real Spec II replay; a replay under another prefix is listed as skipped, not lost.
- CoreGS 2.0 is still in development and is not offered; GSdx is the renderer.
- OpenGL is not offered yet (it needs a new gt4-gs release).
- Direct3D 12 and Direct3D 11 are new options. Vulkan is the tested default; use Direct3D 11 only on PCs where Vulkan
  is not available.
- GT mode in Spec II needs game data created in-game, like v2.00; the first start offers the creation flow.
- Spec II at ultrawide ratios only (wider than 16:9; owner test on rc4, 3440 x 1440): the race HUD's speed figure and odometer digits are
  stretched and spill past their place on the gauge. Only Spec II; GT4 v2.00 is fine. To be fixed in a later update.
- The Spec II logo on the home screen is a placeholder (the GT4 logo with a "Spec II" line) until the authors' logo is
  added.
- Every known issue of 1.2.3 is still open.

## Requirements

- Windows 10 or 11, 64-bit.
- A Vulkan-capable GPU for the default renderer (Direct3D 12 or 11 as alternatives). The PCSX2 GS (`gt4-gs.exe`) runs
  in its own process and is downloaded by the launcher (GPL-3.0-or-later, source in its release).
- Your own Gran Turismo 4 (USA, v2.00) disc image for the original game, and your own Gran Turismo 4 Spec II 1.10
  disc image for the mod.
- Disk space: a copy of your disc image (about 5.2 GB for the v2.00 image; the Spec II image is about 3.7 GB) plus the
  prepared files, for each game you install.
