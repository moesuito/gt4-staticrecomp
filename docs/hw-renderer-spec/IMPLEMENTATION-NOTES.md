# Implementation notes (TASK-027)

Interpretations made by implementers where the specification was silent or
ambiguous. The specification team should confirm or correct each item; until
then they are binding for the implementation.

Ids are unique per milestone; where two milestones used the same number, the id is qualified as IN-nn/<milestone>. New rows use the range assigned in the agent brief.

| IN-442 | CORE2: constant fills as compute | Storage writes from compute run about twice as fast as from the fragment stage at 12x (a fragment-stage pass has a 0.40 ms launch floor). An untextured sprite batch with no blend, fog or DATE (the renderer marks it `constantFill`) is drawn by `core2_fill.comp` when `Gpu::Draw` finds every vertex with the same colour and Z, every primitive an axis-aligned rectangle, and the covered rectangles disjoint or repeated (a repeated rectangle of one constant fragment rewrites what it wrote). Covered pixels follow the rasteriser: hw_vertex.vert puts an edge at scale * X + shift / 2 - 1/320 and a pixel is covered when its centre is on or right of the left edge and left of the right one; the 1/320 bias keeps every edge 0.003 pixel or more from a centre, more than the float rounding, so a double-precision count matches (GT4's clears sit on half-pixel coordinates, -0.5..63.5). Clipped by the draw's own scissor rectangle. The shader builds the fragment as the uber shader does (colour, Z from the rasteriser depth at scale or the varying at 1x, the dither cell) and runs the same hw_process_pixel with the same reads (IN-438) and the CT24 top byte rule.
