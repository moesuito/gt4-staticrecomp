## Slice 88: live no-card session — the semaphore id-space collision (root cause of the park)

Owner-ordered live observation. The owner removed the memory card (the model
has no card services) and asked for a fresh capture; the session ran three
runs against the bundled PCSX2 (**actually v2.9.114** — folder name stale),
software renderer, BIOS v02.30, PINE 28011, savestate format version
`0x9a590000` (same as the old v2.9.93 states — the skew concern is resolved
by the version match).

Findings:

- **No-card behavior (Confirmed, owner-visible + captured):** a "no memory
  card" notice, the intro movie, then the **main menu with no input**
  (Gran Turismo Mode greyed). With a card but no GT4 save, the boot blocks at
  the "create game data?" dialog instead.
- **Reference early sequence (Confirmed, 1 s cadence):** BSS zeros (t≈2 s) →
  table init -1s (t≈6 s) → A/B/C stamped with **distinct** handles
  (A=0x11E/raw 30, B=0x10D/raw 13, C=0x10F/raw 15, t≈8 s) → job submitted
  (+0x34=1, four live args, t≈10 s) → stable through the menu/movie loop.
  The "recreation" the old slices inferred happens **before the save/menu
  screens**, within seconds of game start.
- **Model anomaly (Confirmed):** B and C are stamped at ~service 140
  (B=0x13F/raw 63, C=0x147/raw 71); A is stamped at ~service 1913 with
  **the same handle as B** (0x13F) and the generation table does not change.
  `--steps` bisection pinned the store to `0x00548520 sw v0,0x0(s0)` (init
  0x00548500) after the create wrapper 0x005782E8.
- **Root cause (High confidence):** the model's semaphore allocator hands out
  raw ids 3, 7, 11, … (start 3, step 4, monotonic). The 80th allocation is
  `3+4×79 = 319 = 0x13F`. The game composes `handle = (gen<<8) | raw` and
  decodes `id = handle & 0xFF`, so raw 319 produces the handle **0x13F** —
  colliding with raw 63's handle. The gate's waits on A and B then hit the
  same model semaphore: the slice-78 "2 units for 3 takes" knot is a
  **model-side collision**, not a guest-side knot. The generation write for
  raw 319 landed at `0x00874A4C` (index 319, past the 256-entry table) and
  flipped 0→1 — a confirmed out-of-bounds side effect.
- Key savestates archived under ignored
  `private/pcsx2/sstates/slice88-live-no-card/` (t=2 s/6 s/8 s/10 s + the
  with-card dialog state); full evidence in
  `docs/reverse-engineering/slice88-live-no-card-session.md`.

Next: slice 89 — make the model's semaphore ids stay within 0..255 with slot
reuse (the contract the game's handle math assumes), update the kernel tests,
and re-run the boot: the expected observable is A/B/C distinct and the job
submitted (+0x34=1) with the differential green. Also check the thread-id
