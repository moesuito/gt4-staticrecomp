## TASK-129: silent audio fallback when no output device is present (issue #93)

- Investigated GitHub Issue #93 ("Crashing", reported by @deviljinsuresh; duplicate #94).
- Root cause forensic analysis:
  - Game crashed immediately on startup when launched on systems with no active Windows audio output device:
    `[window] fatal error: waveOutOpen stereo16/48000: Specified device identifier is out of range (2)`.
  - WinMM error code `2` (`MMSYSERR_BADDEVICEID`) is returned by `waveOutOpen` with `WAVE_MAPPER` when `waveOutGetNumDevs() == 0`.
  - `check_audio()` threw a fatal `std::runtime_error`, unwinding `run_window()` and aborting execution before the game initialized.
- Pacing & architectural interaction:
  - Default `GT4_PACING=audio` slaves frame presentation to audio buffer consumption.
  - In silent mode without an audio device, the frame pacer must automatically demote from `Mode::audio` to `Mode::paced` to ensure the high-resolution timer (`QueryPerformanceCounter`) maintains exact 60.0 FPS pacing without waiting for audio buffer consumption.
- Resilient dummy sink design:
  - `AudioOutput` detects missing hardware (`waveOutGetNumDevs() == 0` or `GT4_AUDIO=none/silent/off`) and sets `has_device_ = false`.
  - `push()` accepts stereo PCM samples, updates internal accounting, and returns `true`.
  - `pump()` and `close()` execute safely without interacting with WinMM hardware drivers.
- Authored detailed study: `docs/AUDIO-SILENT-FALLBACK-STUDY.md`.
- Updated `TASKS.md`, `docs/ISSUE-TRIAGE.md`, and `docs/STATUS.md`.
