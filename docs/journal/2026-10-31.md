## TASK-124 / TASK-127: Startup Failure and Flashing Window Forensic Diagnosis (Issues #107 & #99)

- **Forensic Investigation (Issue #107 / TASK-124):**
  - Analyzed user log bundle (`GT4Recomp-logs-20261026-024759.zip`) from reporter `@jannuk0101` on 1.2.4 and 1.3.0-rc5.
  - Determined that the crash code `Some(-1073741515)` corresponds to NTSTATUS `0xC0000135` (`STATUS_DLL_NOT_FOUND`).
  - Identified that process creation aborted in `ntdll` during static import resolution before entering `main()` (leaving an empty 0-byte `game.log`), caused by missing Microsoft Visual C++ 2015–2022 x64 runtime libraries (`vcruntime140.dll`, `msvcp140.dll`, `msvcp140_atomic_wait.dll`) or graphics runtime dependencies on fresh Windows environments.
- **Forensic Investigation (Issue #99 / TASK-127):**
  - Analyzed user log bundle (`GT4Recomp-logs-20261025-094852.zip`) from reporter `@Rafeku` on 1.2.2, 1.2.3, and 1.3.0-rc5.
  - Determined that the crash code `Some(-805306369)` corresponds to NTSTATUS `0xCFFFFFFF` (`STATUS_APPLICATION_HANG`).
  - Identified that under extreme workload (6x upscale / 3840x2688 internal resolution, Ultrawide 3440x1440, ShadeBoost) and unthrottled presentation (`vsync = "off"`, `DisableMailboxPresentation = true`), swapchain acquisition stalls starved the Win32 message pump, causing DWM to repeatedly create and destroy ghost windows (perceived as flickering/flashing) until Windows Error Reporting terminated the hung process.
  - Verified with the reporter that swapchain synchronization fixes in 1.3.0-rc6 successfully resolved the issue for their setup.
- **Launcher Enhancement (`gt4l-core::exit`):**
  - Updated `user_message` in [`launcher/crates/gt4l-core/src/exit.rs`](launcher/crates/gt4l-core/src/exit.rs) to detect `0xC0000135` and `0xCFFFFFFF` and provide actionable plain-language explanations instead of negative decimal integers.
  - Added hex formatting `0x{:08X}` for high NTSTATUS exit codes (`>= 0x80000000`).
  - Added unit test cases covering all new exit code mappings.
