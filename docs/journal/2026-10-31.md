## TASK-126: forward keyboard messages to PCSX2 GS child window for ReShade (Issue #102)

- Forensic analysis and implementation study authored in `docs/RESHADE-HOME-KEY-ISSUE102-STUDY.md`.
- Analyzed upstream Issue #102 ("Cant use Home (Pos1) Keys while in Game for reshade"):
  - User reported ReShade installed in `GT4Recomp\data\gs\1.2.1` (`gt4-gs.exe`) in fullscreen cannot be toggled with Home (Pos1).
  - Cause: In `GT4_RENDERER=pcsx2` mode, the renderer runs out-of-process (`gt4-gs.exe`) and attaches its window as a child of `game_window`.
  - In `native/window.cpp`, `game_window` retains Win32 keyboard focus (`SetFocus(window)`) to prevent controller disconnection on mouse clicks.
  - Because Windows routes keyboard messages solely to the window with focus, the child window in `gt4-gs.exe` never received `WM_KEYDOWN`/`WM_KEYUP`/`WM_CHAR` messages.
- Resolution:
  - In `native/window.cpp`'s `window_procedure`: forward unhandled keyboard messages in `WM_KEYFIRST`..`WM_KEYLAST` to child windows via asynchronous `PostMessageW`.
  - Non-blocking: zero latency impact on the game loop.
  - Allows ReShade (and other overlays hooked into `gt4-gs.exe`) to intercept `VK_HOME` and text input while preserving game controller polling.
