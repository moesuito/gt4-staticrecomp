## TASK-104: save import allocation boundary fix for PCSX2 memory cards (issue #86)

- Investigated GitHub Issue #86 ("Save import from PCSX2 crashes the app", reported by @Dizzee112).
- Root cause forensic analysis:
  - In 1.3.0-rc5, importing `Mcd001.ps2` failed with `"The memory card is damaged (chain entry 7937 outside the allocation area)"`.
  - In `gt4saves::card::Layout`, usable allocation clusters were computed as `alloc_end - alloc_offset`.
  - In Sony PS2 MCFS, `alloc_end` is already relative to `alloc_offset`. Subtracting `alloc_offset` again discarded 41 valid clusters at the end of the card.
  - On memory cards formatted with non-standard allocation boundaries (e.g., `alloc_end = 7978` generated by PCSX2 or third-party formatters), computing `7978 - 41 = 7937` set `usable = 7937`.
  - Legitimate game save data allocated at relative cluster 7937 (physical cluster $41 + 7937 = 7978 < 8192$, safely inside physical NAND flash) was rejected by `if current >= usable`.
- Established proper physical capacity bounds:
  - `Layout::usable()` defined as `self.clusters.saturating_sub(self.alloc_offset)` (e.g. 8151 clusters on an 8 MB card).
  - All clusters physically fitting on the flash memory card are safely readable while strictly preventing out-of-bounds reads and loops.
