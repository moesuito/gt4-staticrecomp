## M26 — the whole-text translation survey

- `gt4translate` gained a `--survey` mode (the walk was factored into
  `collect_units`, so one function and the survey share the same
  validation). It treats every direct-call target in the text as an entry:
  **15,067 unique `jal` targets over 97,269 call sites**.
- Results: **9,345 entries translate (62%)**; their trees cover 399,046
  instructions (~30% of the real code region). Rejections: **4,576 `jalr`
  indirect calls, 1,055 computed `jr` jumps** (93% of all rejections), plus
  non-code `jal` targets and a few validation edges. The survey runs in
  ~15 seconds.
- Conclusion: instruction coverage is effectively complete; **indirect
  control flow is now the limiting factor** for translation. The survey
  itself enumerates the function entries a dispatch table would need.
- A Python CLI smoke test covers the mode; CTest 24/24; Python 72.
- Next: M27 indirect control flow (dispatch through registered entries,
  stopping with context on unknown targets).

## M25 — the translator reaches the macro and trapping operations

- `ee::execute_plain_effect` exposes the verified executor (same code path as
  the interpreter, pc untouched, false on a trapping overflow) and the
  translator falls back to it for every decoded plain operation without an
  inline form: the whole VU0 macro table, the COP2 moves and quad accesses,
  the remaining MMI forms and the trapping arithmetic. The trapping statement
  stops the module at the instruction's address when the overflow fires,
  exactly where the interpreter stops.
- **A new verified module: 0x0056DF58**, a 133-instruction vector
  convert/scale loop with 32 runtime-executed instructions (pextlw, pmaxw,
  pminw, pcpyld, pcpyh, pmfhl, pcpyud, pmadduw, pmulth among them), matching
  the interpreter on 3 input states: all registers, both HI/LO banks, the pc
  and the whole scratch memory window compare equal.
- CTest 24/24; Python 71 (65 run, 6 skip).
- Next: a whole-text translation survey to see which functions translate
  today and what blocks the rest.

## M24 — the trapping arithmetic and the parallel multiply/divide family

- The six trapping forms (ADD/SUB/DADD/DSUB/ADDI/DADDI) execute with the
  reference's exact overflow checks — including the negation-before-check of
  the subtract forms and its edge-case quirk — and stop with the stable
  Exception outcome at the offending word when the check fires; the
  destination is untouched and the handler is not modeled (like SYSCALL and
  BREAK).
- Eight parallel multiply/divide operations join: PMADDH/PMSUBH/PMULTH over
  the eight halfword lanes with the destination packing, and
  PMULTW/PMULTUW/PMADDUW/PDIVW/PDIVUW over the HI/LO pair with the
  reference's special cases (the $80000000/-1 division pair, zero divisors,
  unsigned wraparound).
- Whole-file unsupported words: 672 → **497**; the real code region
  (0x00100000..0x616F1C) now holds only **4 words** — two BC0F waiting for a
  DMA model for their condition line, and two words at unassigned function
  0x28 inside the exception handler's register-dump code. 349 operations.
  CTest 23/23; Python 71.
- Next: translating the VU0 macro operations and the trapping forms so the
  translator can cover functions that use them.

## M23 — the full VU0 macro instruction set

- The complete macro table lands: 111 new operations (335 total) covering
  both dispatch tables — the float model (denormal flush, overflow clamp at
  the reference's default settings), the MAC/status flag registers with their
  exact syncs, the element/broadcast/accumulator arithmetic, min/max, the
  outer products, the conversions, VCLIPw, the moves, the division unit with
  Q publication, VMTIR/VMFIR, the random generator and the 16-bit integer
  forms. VCALLMS/VCALLMSR and the VU0-memory forms stop with context.
- Semantics were mirrored from the reference sources (`VUops.cpp`,
  `VUflags.cpp`, `VU0.cpp`, `R5900OpcodeTables.cpp`, `Config.h`) after a
  purpose-built probe listed the macro families the game actually uses
  (vmove 83, vmulax 81, vmadday 77, vmaddw 57, vnop 88 among them).
- **The whole-text scan dropped from 1,426 to 672 unsupported words — and the
  scan exposed that the text section's last 700 words (0x616F28..0x617A14)
  are a data table**, not code: those values only decode as instructions by
  coincidence. In the real code region (0x00100000..0x616F1C) only **81
  unsupported words** remain, in known families: the trapping arithmetic (70),
  MMI2/MMI3 parallel multiply (7), COP0 BC0F (2) and two words at unassigned
  function 0x28.
- Fixtures: decode/disassembly cases for hand-assembled and observed words,
  an interpreter scenario with hand-computed values (including the
  reference's status-register high-bit quirk). CTest 23/23; Python 71.
- Next: the trapping arithmetic forms (they need the exception outcome), the
  MMI parallel multiply and COP0's BC0F.

## M22 part 1 — VU0 macro state, moves and the quad memory accesses

- The VU0 macro-mode state joins the guest model: 32 vector registers of four
  32-bit lanes (register 0 hardwired to the constant (0, 0, 0, 1.0)), the
  integer file (VI0 zero), the clip flag, and the FBRST reset that clears the
  file.
- Moves: QMFC2/QMTC2 (the full 128 bits through both GPR halves), CFC2/CTC2
  with the reference's exact cases (the reciprocal register's mantissa mask
  and constant exponent, read-only MAC_FLAG/TPC/VPU_STAT, the FBRST mask with
  its VU0-reset, CLIP_FLAG's double write, context stops for the VU1
  controls), LQC2/SQC2 (16-byte alignment; constant-register loads still
  access and discard), and VNOP (`0x4a0002ff`, the packed SPECIAL2 index 47)
  — 224 operations in total.
- The macro families were measured from the pinned text before coding: the
  moves and quad accesses (~750 words) dominate, then VMULAx/y/z/w and VNOP.
  The dispatch is decoded for part 2: functions 0x00-0x3B through the
  standard table; 0x3C-0x3F through the packed
  `(word & 3) | ((word >> 4) & 0x7C)` index the reference computes.
- Whole-text unsupported count: 2,269 → **1,426** (the moved families); the
  first 350,000 words stay at zero. CTest 23/23; Python 71 (65 run, 6 skip).
- The probe that measured the families needed zlib in its link line
  (`build/_deps/zlib-build/zlibstaticd.lib`); recorded so the next probe does
  not repeat the detour.
- Next: the macro arithmetic (VADD/VMUL/VMADD/VDIV/... with the vector flag
  semantics) through the decoded dispatch.

## M21 — trap slots, ERET, and the largest verified module

- The `beql …; break` trap in a likely delay slot is fully represented: the
  flow walker flags the slot (`delay_slot_traps`), the interpreter stops at
  the trapping word with the Exception outcome when it fires (and skips the
  slot when not taken), and the translator emits
  `if (taken) { set_pc(slot); return; }`.
- `eret` decodes and executes with the CP0-derived target and level clear; in
  translated code it is a boundary that derives the pc from CP0 and returns.
- Translator emission gaps closed: lhu/lwu/sh, dsubu (the trapping dsub stays
  unsupported), mult/multu/div/divu + second-bank forms via mirroring helpers,
  mfhi/mflo/mfhi1/mflo1.
- **Two new verified modules**: `0x00579780` (66 instructions, 6 states) and
  `0x0058ce48` — **57 functions, 2,588 instructions** — the whole tree this
  session peeled one gap at a time, verified on 4 states with identical
  registers, HI/LO and the compared memory windows. CTest 23/23; Python 71.
- **Scan correction**: my earlier "the entire text decodes" claim was a false
  positive — chunks 2-4 used ranges beyond the text end and the tool's error
  was read as a clean scan. The ERET sighting in real code exposed it. The
  honest numbers: 2,269 unsupported of 1,334,917 (0.17%), dominated by VU0
  macro (COP2, ~1,250), LQC2/SQC2 (378), trapping arithmetic (123), DADDI
  (23), MMI2/MMI3 parallel multiply (14). First 350,000 words: zero
  unsupported. Lesson recorded in the M20 doc: a scan must check the tool's
  exit status, not only its output.
- Next major block: VU0 macro mode (the curriculum's M15-M17), needing its
  own vector register file and semantics.
