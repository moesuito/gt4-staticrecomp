## M21 — trap slots, ERET, and the largest verified module

- The `beql …; break` trap in a likely delay slot is fully represented: the
  flow walker flags the slot (`delay_slot_traps`), the interpreter stops at
  the trapping word with the Exception outcome when it fires (and skips the
  slot when not taken), and the translator emits
  `if (taken) { set_pc(slot); return; }`.
- `eret` decodes and executes with the CP0-derived target and level clear; in
  translated code it is a boundary that derives the pc from CP0 and returns.
- Translator emission gaps closed: lhu/lwu/sh, dsubu (the trapping dsub stays
  unsupported), mult/multu/div/divu + second-bank forms via mirroring helpers,
  mfhi/mflo/mfhi1/mflo1.
- **Two new verified modules**: `0x00579780` (66 instructions, 6 states) and
  `0x0058ce48` — **57 functions, 2,588 instructions** — the whole tree this
  session peeled one gap at a time, verified on 4 states with identical
  registers, HI/LO and the compared memory windows. CTest 23/23; Python 71.
- **Scan correction**: my earlier "the entire text decodes" claim was a false
  positive — chunks 2-4 used ranges beyond the text end and the tool's error
  was read as a clean scan. The ERET sighting in real code exposed it. The
  honest numbers: 2,269 unsupported of 1,334,917 (0.17%), dominated by VU0
  macro (COP2, ~1,250), LQC2/SQC2 (378), trapping arithmetic (123), DADDI
  (23), MMI2/MMI3 parallel multiply (14). First 350,000 words: zero
  unsupported. Lesson recorded in the M20 doc: a scan must check the tool's
  exit status, not only its output.
- Next major block: VU0 macro mode (the curriculum's M15-M17), needing its
  own vector register file and semantics.
