## TASK-077: Context-aware input mapping (race vs menus)

Completed TASK-077, providing native context-aware input mapping separating race controls from menus and garages without modifying guest code or translated units.

- **Host-side Context Probe (`native/context_probe.{hpp,cpp}`):**
  - Reads guest RAM at VBlank using safe, range-checked memory loads starting from game owner pointer `0x622F4C`.
  - Recognizes 10 virtual table addresses for race classes (`RaceGTmode`, `RaceArcade`, `RaceFreeRun`, `RaceLicense`, etc.).
  - Distinguishes attract demo (`RaceArcadeDemo`) and classifies it logically as `Menu`.
  - Detects active pause object at `race + 0xE418` (`RacePause`, `SimplePause`, `PhotoPause`).
  - Implements 3-frame debounce filtering to prevent spurious intermediate states during scene transitions.
  - Employs cached offset acceleration to resolve race object pointers in O(1) on subsequent frames.
- **Input Transition Filtering (`native/context_input.{hpp,cpp}`):**
  - Implements the re-arm rule: any key (Win32 VK) or gamepad button held across a context boundary is disarmed until physically released and re-pressed.
  - Implements clean transition frames: all logical buttons are released on the exact frame a context change occurs.
  - Implements loading screen lock: buttons are held neutral while in `Loading` context.
- **Schema 2 Configuration (`native/controls.{hpp,cpp}`):**
  - Added support for `schema = 2` with context override tables (`[bindings.race]`, `[bindings.pause]`, `[bindings.menu]`, etc.) while maintaining 100% backward compatibility with `schema = 1`.
  - Built-in defaults map `Esc` to `Start` (pause) in races, and `Triangle` (back) in menus.
