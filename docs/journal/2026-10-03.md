## M30 slice 46 — the font file's load path: the copy-out cursor (the fix)

- **The load path** (temporary RPC/file traces, removed): the whole boot
  reads 12 disc blocks; the font loads as 3 late PRTS reads (`0x1BFBF`,
  `0x1BFA3`, and 186 KB at `0x1C878`) with no fileio/PCDV involvement;
  only `IRX` opens ever occur. Disc bytes are packed (no `FT01`).
- **The divergence**: the font block streams out as seven 0x4000-byte
  copy-outs into alternating buffers, but the request carries no offset
  and the model re-served chunk zero every time — the object was built
  from one chunk repeated (hence the patterned buffer and the odd
  "pointer"). A server without per-handle position cannot serve this
  protocol, so the cursor is required.
- **The fix** (decision 0021 extended): per-handle cursor, served from
  and advanced, clamped, destination validated; tests cover sequential
  chunks, exhaustion, unknown handle, outside-image read, disc-less box.
- **Verification**: the 10x run sails past the 15,010,045-service fault
  to its step limit — **41,919,339 services** (65.4M module calls, 1.93B
  interpreted steps), clean stop at `0x005552b0`, healthy threads.
- CTest 36/36, Python 73 (67 run, 6 skip); instruments removed
  (`docs/reverse-engineering/m30-slice46-the-copy-out-cursor.md`).
