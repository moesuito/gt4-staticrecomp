## TASK-136: PCSX2 GS portable mode to avoid OneDrive Documents startup crash (issue #131)

- Diagnosed Issue #131 where the game crashes on startup with 	he GS process gt4-gs.exe exited during the handshake (code 1).
- Root cause verified via clean black-box execution of gt4-gs.exe:
  - When invoked without portable mode, gt4-gs.exe calls SHGetKnownFolderPath(FOLDERID_Documents).
  - On Windows installations where the Documents directory is redirected to Microsoft OneDrive (e.g., C:\Users\<user>\OneDrive\Documentos\PCSX2), OneDrive sync locks, network folder states, or permission restrictions cause PCSX2's early static config initialization to fail before --config argument parsing.
  - It logs [ 0.0041] Failed to initialize config. and terminates with exit code 1.
  - When portable.ini exists alongside gt4-gs.exe in its directory (AppRoot), PCSX2 detects portable mode and sets DataRoot Directory directly to AppRoot, completely avoiding any query to FOLDERID_Documents or OneDrive.
- Implementation:
  - Added PORTABLE_MARKER = "portable.ini" and ensure_portable_marker(&Path) in launcher/crates/gt4l-core/src/gs_release.rs.
  - Enforced ensure_portable_marker during release extraction (stage_and_publish) and verification (check_installed).
  - Added portable marker check to Pcsx2Paths::for_session in launcher/crates/gt4l-core/src/launch.rs so that existing GS installations automatically gain portable.ini upon launch.
  - Added fallback portable marker creation in 
ative/gs_stream/gs_stream_client.cpp before spawning the child process for non-launcher or direct CLI/test invocations.
  - Added unit test portable_marker_is_created_and_restored_if_removed in launcher/crates/gt4l-core/tests/gs_release.rs.
