## TASK-114 item 8: Settings open at once

- **Extended to Games, Saves and Replays.** `games_list`, `saves_list` and `replays_list` are prefetched with the rest
  (`GT4.prefetchSettings`) and kept in `GT4.cache` (`games`, `library.saves`, `library.replays`). Their pages draw from memory,
  read again behind, and draw again only on a change, keeping focus on the row. Every answer of the list and change
  commands (import, new save, rename, delete, activate, remove a game) updates that list. The loading line replaces the empty
  state until a list is known, so Saves and Replays no longer flash "no saves" before the list arrives. The first draw of
  each page gets the entrance. One focus check (a loaded Saves tab shows its list at once); en-US 195/195, pt-BR 202/202.

- **Cause (confirmed by reading the code).** `get_settings_table_with_monitors` probed the graphics cards twice on every
  call (`integrated_gpu_name`, then `probe_gpus`), and each probe creates a Vulkan instance and enumerates DXGI. The
  settings save (`write_standalone_files`) and Play did the same. The tab waited for that before drawing "Loading settings...".
- **Probes per action** (from the code paths; the cached paths are checked by unit tests): start 1 (unchanged); open a
  Settings tab 2 to 0; save a setting 2 to 0; Play 3 to 1 (the one refresh); export logs 1 to 0. The first Settings open,
  if it comes before the start-up probe ends, probes once.
- **Rust.** `gt4l-platform::gpu` keeps the card list in `GpuCache` (`cached_gpus`, `refresh_gpus`, `store_gpus`,
  `get_or_probe`, `refresh`, `store`); `integrated_gpu_name_of` and `run_settings_with_cards` take a list and probe nothing.
  `probe_count()` counts real probes on the thread (the test hook). Six new tests: the cache, refresh, the start-up store,
  the pure integrated rule, a run over known cards, and the settings table reading the cache.
- **UI.** `settings.js` keeps `cache` (table, About, versions); `prefetchSettings` runs from `app.js` once home is drawn.
  A tab with data draws at once and reads again behind it; a read that finds the same table draws nothing. A write or a
  reset draws at once. About and the Version row follow the same rule. The entrance is `enterAnimation` (CSS `.enter-item`
  in `app.css`, `--enter-delay` from JS, off with reduced motion).
- **Not done.** The Home notes card has no entrance (left alone, as asked).
- **Flake seen.** `flow_audit::a_1_2_x_install_moves_into_games_gt4_at_the_first_start` failed once on this branch and once
  on the base code (stashed), then passed on later runs. It is the same flake the 1.3.0-rc5 journal records; not investigated.

## TASK-114 item 9: dropdown values on one line (rc5 owner screenshot)

- **Cause.** The pt-BR owner screenshot showed "Automático (Português (Brasil))" on two lines in the Language dropdown. The
  value text had no `nowrap`, and the 190 px control was too narrow for it. The Language value at 12.5 px is about 174 px,
  more than the 149 px the value has inside a 190 px control.
- **Value.** `.select > span:first-child` in `app.css` is nowrap, cut with an ellipsis, and has a fixed 16 px line height.
  `settings.js` puts the full text in the value's `title` (set at start, on every choice and on the Version row). The
  Language row is a wide control (`wide: row.id === "language"`, `.row .ctl.wide .select` fills it). Long names in the opened
  list may wrap but stay inside the panel (`.option > span:first-child`).
- **Other dropdowns.** Graphics API "Automático (Direct3D 11)" measures 149 px and fits. Monitor names and graphics card
  names longer than the control are cut with an ellipsis; the full name is in the tooltip. No other control was made wide.
- **Checks.** `dev/focus-check.js` has `selectValueChecks`: every `.row .select` on General and Graphics is one line
  (value height at most its line height, nowrap), and the Language value stays one line with its longest text. Both languages
  pass (en-US 198/198, pt-BR 205/205). Against the previous CSS and JS the new checks fail (the Language value was 36 px tall
  instead of 18 px). nav-test 150/150. No Rust changed, so no `cargo test`.
- **Screenshots.** `O:\gt4recomp-scratch\slice295-shots\general-pt-BR.png` and `graphics-pt-BR.png` (1280x720, Edge headless,
  `?os=pt-BR` so Language is on Auto as in the owner's screenshot). New scenarios `?scenario=general` and `?scenario=graphics`
