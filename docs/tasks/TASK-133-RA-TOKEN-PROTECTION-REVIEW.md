## Findings requiring fixes

1. **Migration failure can erase the old token on an unrelated option change.** `RaConfig::load_with` clears the in-memory token and sets `token_error` on a failed migration while preserving the original legacy file (retroachievements.rs lines 138-170). `ra_set_options_of` then changes flags and calls `save` (commands.rs around 1734); `save_with` clears the serialized token and, with no protected envelope, writes that config (retroachievements.rs around 197-214). Thus if protection/verification fails persistently but writing succeeds, an option toggle overwrites the still-plaintext legacy token. Prevent unrelated mutations from destroying the prior file after migration failure. Differentiate storage/migration failure from an unprotectable already-encrypted token and from intentional logout. Explicit successful logout or successful replacement login may have distinct semantics; test them. Preserve original bytes on protect, verification, serialization, temporary write and replacement failures, including retry and option update, without generating plaintext temporary/backup files or using real accounts.
2. **Malformed non-ASCII ciphertext can panic.** `secret::hex_decode` slices `&s[i..i+2]` by byte indices without checking UTF-8 character boundaries. For example an even-byte malformed value `dpapi:v1:aéa` enters a slice inside a multibyte character. Make parsing byte-safe, bounded and return an error for arbitrary malformed input; do not leak content. Test odd/even UTF-8/non-ASCII, bad prefix, bad hex, empty/truncated/tampered ciphertext and normal DPAPI data. Ensure launcher surfaces recoverable localized state and preserves stored data rather than crashing.
3. **Storage failures need correct UI and error behavior.** All `token_error` values currently produce the same “cannot be unlocked on this Windows account or PC” banner, including inability to protect/save an old token. The plan requires distinguishing migration/storage errors from an inaccessible encrypted session. Introduce safe typed/error categories and accurate localized user guidance in English and Portuguese without exposing token bytes, preserving non-secret settings. Test at launcher command/UI level with fake errors and no live credentials.
4. **Audit debug and serialization paths for secrets.** `RaConfig` derives `Debug` and includes the decrypted `token`; serialization also permits a nonempty token. Trace actual diagnostic, error and logging paths and ensure no accidental token/password emission in `Debug`, exported support bundle, argv, or temp files; write meaningful synthetic-secret regression tests. Avoid claiming DPAPI protects all stolen disks/users; document its actual user-bound limits and historical plaintext backups.
5. **Validate race, write and profile behavior requested in the original brief.** Existing failure test covers protect error on load only; it does not exercise the subsequent option write or an injected write/replace interruption. Add deterministic tests for save failure paths, successful migration and fresh login/logout, independent installed/two portable roots, account refresh/newer login/logout/target switch with real command layer and bounded fake network/store. Confirm the token cannot reappear or be erased by a stale action. Preserve the original revision fencing and Spec II isolation.
6. Fix unrelated full-file line-ending churn introduced by this commit in locale/UI/Rust/notes files while preserving intentional code and repository blob conventions. Use safe explicit staging; never reset others' files. Report meaningful source diff.
