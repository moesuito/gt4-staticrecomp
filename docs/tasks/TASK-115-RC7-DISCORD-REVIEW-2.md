## Confirmed findings

1. `DiscordIpcTransport::connect` calls `CreateFileW` with `Default::default()` flags (line 71), not `FILE_FLAG_OVERLAPPED`. The Windows named-pipe handle is synchronous, so passing `OVERLAPPED` to read/write does not establish the claimed nonblocking timeouts; calls may block before the event wait is reached. Microsoft: https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-client and https://learn.microsoft.com/en-us/windows/win32/ipc/synchronous-and-overlapped-input-and-output .
2. On timeout, both `write_frame` and `read_exact` call `CancelIoEx`, wait at most one second, ignore the wait result, close the event and return, dropping the stack `OVERLAPPED` and associated read/write buffer even if completion was not observed. This can leave OS I/O referencing released memory. `CancelIoEx` requests cancellation, not completion: https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex . This is a memory-safety blocker. Fixing only the open flag is insufficient.
3. `apply_toggle(false)` and `on_game_end` detach a new thread before it sets `stop`; the generation changes only on a new start. There is a window after disable/end returns in which the old session may still send. Old sessions unconditionally send a clear on exit, which can race with a newer session. Launcher exit spawns detached cleanup threads then returns, so clear is not guaranteed before process termination. Repeated toggles can leave detached workers; `retired` is not populated. Design and prove cancellation, cleanup and ordering rather than claiming guarantees from a short wait.
4. The first activity acknowledgment is discarded (`let _ = t.read_frame`) and any op 1 is accepted as handshake. Error recognition uses exact substring matching; read errors are all treated as idle timeout. Incoming ping is not answered as pong. Validate messages and lifecycle according to credible primary protocol documentation or a verified maintained library; distinguish explicit error, partial frame, broken connection and timeout. Do not assert a successful presence without a verified response and real owner test.
5. Test `reconnect_preserves_timestamp` toggles off/on and does not simulate transport disconnection/reconnection; `generation_fence_blocks_stale_session` only checks a session exists; the tests use sleeps and don't prove safety under controlled races. The large line-ending-only diffs in `settings.rs` and `state.rs` remain. The STATUS entry incorrectly calls this reviewed/corrected; supersede it honestly while preserving history.
